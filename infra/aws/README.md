# AWS EC2 IaC

Backend deployment infrastructure.

Scope:

- EC2 API runtime
- PostgreSQL RDS in the same VPC
- backend image pulled from GHCR or another container registry
- no custom domain
- no HTTPS
- API reached by public EC2 IP and backend port

Resources:

- EC2 instance for Dockerized Go API
- security group for SSH and API port
- Elastic IP

## Target Shape

```txt
Vercel frontend
  FOODLINK_API_ORIGIN=http://<elastic-ip>:8080
  browser calls same-origin /api/v1 through Next.js rewrites

AWS EC2 backend
  Docker container listens on :8080
  public access allowed to :8080
  SSH access restricted to local IP

AWS RDS
  private PostgreSQL endpoint
  inbound 5432 allowed only from the API security group
```

## Terraform Resources

- `aws_security_group`
- `aws_vpc_security_group_ingress_rule`
- `aws_instance`
- `aws_db_instance`
- `aws_db_subnet_group`
- `aws_eip`
- `aws_eip_association`
- `random_password`

## Security Group Rules

- inbound SSH: TCP `22`, source = your current public IP only
- inbound API: TCP `8080`, source = `0.0.0.0/0`
- inbound PostgreSQL: TCP `5432`, source = API security group only
- outbound: all traffic

No inbound `80` or `443` needed unless adding reverse proxy later.

SSH uses the EC2 key pair named by `ssh_key_name` plus the security group
CIDR allowlist. The example value is `foodlink-prod`, so that key pair must
exist in the target AWS region before `terraform apply`.

## Deployment Plan

1. Terraform reads the account's default VPC and subnets.
2. Terraform creates the API and database security groups.
3. Terraform creates a private PostgreSQL RDS instance and waits for its endpoint.
4. Terraform creates EC2 with a generated `DATABASE_URL` containing the private RDS endpoint.
5. EC2 installs Docker, pulls the backend image, runs migrations, and starts a systemd-managed container.
6. Terraform outputs the backend URL and private database endpoint.
7. Vercel uses `FOODLINK_API_ORIGIN=http://<elastic-ip>:8080` for server-side rewrites.

References in Terraform establish this order automatically. One
`terraform apply` provisions the full stack.

## Prerequisites

Verify AWS credentials and account:

```sh
aws sts get-caller-identity
```

Create the example EC2 key pair if it does not already exist:

```sh
aws ec2 create-key-pair \
  --key-name foodlink-prod \
  --region ap-southeast-1 \
  --query 'KeyMaterial' \
  --output text > ~/.ssh/foodlink-prod.pem

chmod 400 ~/.ssh/foodlink-prod.pem
```

Use your current public IP for `ssh_allowed_cidr_blocks`:

```sh
curl ifconfig.me
```

Set it as a `/32` CIDR in `terraform.tfvars`, for example:

```hcl
ssh_allowed_cidr_blocks = ["203.0.113.10/32"]
```

## Usage

```sh
cp terraform.tfvars.example terraform.tfvars
# edit terraform.tfvars with SSH CIDR, container image, RDS sizing, JWT secret, and allowed origins
terraform init
terraform plan
terraform apply
```

After apply:

```sh
curl "$(terraform output -raw backend_api_url)/health"
```

Inspect the private database endpoint:

```sh
terraform output -raw database_endpoint
```

Logs:

```sh
ssh -i ~/.ssh/foodlink-prod.pem ec2-user@$(terraform output -raw backend_public_ip)
sudo journalctl -u foodlink-api -f
```

To update the allowed SSH IP later, edit `ssh_allowed_cidr_blocks` in
`terraform.tfvars`, then run `terraform plan` and `terraform apply`. Terraform
should update the security group rule in place without replacing the EC2
instance.

The RDS password is generated by Terraform. Terraform state and EC2 user data
contain the database credentials. Store state somewhere private and never
commit it. A later hardening step should move runtime secrets to AWS Secrets
Manager.

For persistent production data, set:

```hcl
database_deletion_protection = true
database_skip_final_snapshot = false
database_multi_az            = true
```

Demo defaults disable deletion protection, skip the final snapshot, and use a
single availability zone to control cost. Backup retention defaults to one day
because AWS Free Plan accounts reject longer retention periods.

## GHCR Image

Use the image published by GitHub Actions:

```hcl
container_image = "ghcr.io/christolx/foodlink-api:latest"
```

If the package is private, set `registry_username` and `registry_token`. If public, omit them.

## Later Upgrades

- add Caddy/Nginx reverse proxy
- add HTTPS
- add custom domain
- add deploy IAM role
- use Secrets Manager for runtime database credentials
- move from the default VPC to dedicated public and private subnets
- store Terraform state in a locked, encrypted remote backend

Do not commit real `*.tfvars` files or Terraform state.
